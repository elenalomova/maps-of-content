# Content by Tags — плагин для Obsidian

## Обзор

Плагин **Content by Tags** автоматически создаёт и поддерживает актуальной карту всех ваших заметок, сгруппированных по тегам. Плагин создаёт одну заметку, которая служит централизованным индексом вашего хранилища — примерно так же, как CMS-системы генерируют файлы sitemap.xml, только для тег-ориентированной организации в Obsidian.

Каждая группа тегов отображается как сворачиваемый тоггл (по умолчанию свёрнутый), внутри которого перечислены заметки этого тега. Плагин постоянно отслеживает хранилище и автоматически обновляет карту при добавлении, изменении или удалении заметок, так что карта всегда остаётся актуальной.

## Основные возможности

### 📋 **Автоматическая организация по тегам**
- **Табличная раскладка**: карта — это единая markdown-таблица с тремя столбцами: дата самой свежей заметки под этим тегом, количество заметок и сворачиваемый тоггл со списком заметок
- **Сворачиваемые тоглы**: список заметок каждого тега отображается как `<details>`-тоггл, по умолчанию свёрнутый, внутри третьего столбца
- **Символ `#`**: названия тегов в тоггле показываются как `# tagname` (с пробелом после решётки), кроме строки «Без тегов» и строки тега `Obsidian` — они показываются без решётки
- **Поддержка нескольких тегов**: заметки с несколькими тегами появляются в строке каждого своего тега
- **Заметки без тегов**: получают отдельную строку, всегда первую в таблице
- **Фиксированный порядок**: «Без тегов» — всегда строка 1, тег `Obsidian` (если есть) — всегда строка 2; остальные строки идут в порядке, заданном настройкой сортировки (см. ниже)
- **Источники тегов**: поддерживаются теги как из фронтматтера (`tags: [tag1, tag2]`), так и инлайновые (`#tag`)

### 🔽 **Сортировка таблицы**
- В шапке таблицы рядом с активным столбцом сортировки (Дата последней заметки / Количество заметок / Тег) показывается стрелка **↓** — так видно, какой режим сортировки сейчас включён.
- Режим сортировки меняется через выпадающий список **«Сортировка строк таблицы тегов»** в настройках плагина, либо через одну из трёх команд в палитре команд: **«Сортировать таблицу тегов: по алфавиту / по количеству заметок / по дате последней заметки»**. В обоих случаях карта сразу пересоздаётся в новом порядке.
- **Это не кликабельный фильтр внутри самой заметки.** Официальная документация Obsidian по санитизации HTML подтверждает, что Obsidian вырезает `<script>` из отрендеренных заметок в целях безопасности (см. [Obsidian Help → HTML sanitization](https://help.obsidian.md)) — поэтому сгенерированная markdown-заметка не может содержать по-настоящему интерактивную, кликабельную сортировку в шапке таблицы. Режим сортировки поэтому управляется извне заметки (через настройки или команды), а не кликом по заголовку столбца.
- Строки «Без тегов» и `Obsidian` не участвуют в этой сортировке и всегда закреплены на местах 1 и 2.

### 🔄 **Умная система автообновления**
- **Отслеживание в реальном времени**: плагин автоматически замечает изменения заметок и обновляет карту
- **Настраиваемый интервал**: можно задать интервал автообновления (1–60 минут)
- **Обновление по событиям**: реагирует на создание, изменение, удаление и переименование файлов
- **Ручное обновление**: карту можно создать по требованию через палитру команд

### 🏗️ **Расширенное управление тегами**
- **Поддержка вложенных тегов**: работает с иерархическими тегами вида `project/work/client`
- **Иерархия тегов**: опционально можно создавать родительские теги для вложенных структур
- **Исключение тегов**: можно исключить отдельные теги (например, `draft`, `private`) из карты
- **Статистика по тегам**: количество заметок под каждым тегом показывается отдельным столбцом таблицы

### 🌐 **Язык интерфейса**
- В настройках плагина появился переключатель **«Язык» / «Language»**: русский или английский.
- Переключает язык у: подписей и описаний в настройках плагина, всплывающих уведомлений (Notice), и текста самой сгенерированной карты (заголовки таблицы, «Без тегов» / «Without tags», подпись «Автоматически сгенерировано» / «Automatically generated», формат дат — `ru-RU` или `en-US`).
- Названия команд в палитре команд плагин пытается переименовать сразу же после смены языка — но это работает через недокументированный внутренний метод Obsidian (`app.commands.removeCommand`), а не через официальный публичный API, поэтому гарантировать его работу на 100% во всех версиях Obsidian нельзя. Если названия команд не обновились сразу — помогает выключить и снова включить плагин в Настройки → Community plugins.
- Названия самих тегов (например, `#travel`, `#library`) не переводятся — переводится только текст интерфейса вокруг них.

### ⚙️ **Гибкая настройка**
- **Своё имя файла карты**: можно выбрать любое имя для файла карты
- **Варианты сортировки**: заметки внутри тоггла можно сортировать по имени, дате создания или дате изменения
- **Исключение папок**: можно исключить отдельные папки (например, `.obsidian`, `.trash`) из обработки
- **Отображение метаданных**: опционально можно показывать дату последнего изменения заметок

### 📁 **Умная работа с файлами**
- **Отображение пути**: для заметок во вложенных папках показывается относительный путь
- **Только Markdown**: обрабатываются только файлы `.md`
- **Самоисключение**: файл самой карты не попадает в саму карту
- **Без декоративных иконок**: сгенерированная страница использует только обычный текст и ссылки — без эмодзи-иконок

## РучнаяУстановка

1. Скачайте main.js и manifest.json
2. Поместите файлы в папку `.obsidian/plugins/content-by-tags/`
3. Перезапустите Obsidian
4. Включите плагин в Настройки → Community Plugins

> **Про переименование:** id плагина изменился с `maps-of-content` на `content-by-tags`. Если вы обновляете уже установленный плагин, Obsidian воспримет это как новый плагин — его нужно будет включить заново, а старую папку `maps-of-content` в `.obsidian/plugins/` можно удалить.

## Использование

### С чего начать
1. **Создайте первую карту**: откройте палитру команд (`Ctrl/Cmd + P`) и найдите «Создать карту тегов»
2. **Автообновление**: плагин будет автоматически обновлять карту по мере изменения заметок
3. **Ручное обновление**: команда «Обновить карту тегов» — для немедленного обновления
4. **Раскрытие разделов**: кликните по заголовку тоггла, чтобы развернуть и увидеть заметки под этим тегом

### Команды
- **Создать карту тегов** — создаёт новую карту содержимого
- **Обновить карту тегов** — вручную обновляет уже существующую карту
- **Сортировать таблицу тегов: по алфавиту / по количеству заметок / по дате последней заметки** — переключает режим сортировки таблицы и сразу пересоздаёт карту

### Когда карта реально создаётся или обновляется?

Плагин **не** создаёт файл карты автоматически в момент включения. Это происходит только в одном из трёх случаев:

1. **Вручную и сразу** — либо командой **«Создать карту тегов»** из палитры команд, либо кнопкой **«Создать карту тегов»** в Настройки → Content by Tags. Это самый быстрый способ создать файл впервые.
2. **После изменения в хранилище** — когда заметка создаётся, изменяется, удаляется или переименовывается (и `autoUpdate` включён), плагин ждёт 3 секунды (чтобы не обновлять карту на каждое нажатие клавиши) и затем пересоздаёт её. Если файла карты ещё нет, это же событие его создаёт.
3. **По таймеру** — если `autoUpdate` включён, плагин пересоздаёт карту каждые `updateInterval` минут (по умолчанию — 5, настраивается от 1 до 60 в настройках).

Если вы только что включили плагин и не запускали ни одно из этих трёх событий — файл карты попросту ещё не существует: используйте кнопку в настройках или команду из палитры, чтобы создать его немедленно.

### Пример вывода

Результат (в режиме чтения, Reading view) выглядит как таблица, где третий столбец содержит свёрнутый тоггл для каждого тега. Обратите внимание: в сгенерированном содержимом нет заголовка — заголовком служит само имя файла заметки, которое Obsidian показывает над содержимым автоматически:

```markdown
*Автоматически сгенерировано: 22.08.2025, 15:30:00*

**Всего заметок:** 25 | **Всего тегов:** 8

| Дата последней заметки | Количество заметок | Тег ↓ |
| --- | --- | --- |
| 20.08.2025 | 3 | <details><summary>Без тегов</summary><ul><li><a href="Random Thoughts.md" class="internal-link" data-href="Random Thoughts.md">Random Thoughts</a></li><li><a href="Meeting Notes.md" class="internal-link" data-href="Meeting Notes.md">Meeting Notes</a></li></ul></details> |
| 22.08.2025 | 4 | <details><summary>Obsidian</summary><ul><li><a href="Notes/Obsidian Setup.md" class="internal-link" data-href="Notes/Obsidian Setup.md">Obsidian Setup</a> (Notes/Obsidian Setup.md)</li></ul></details> |
| 15.08.2025 | 5 | <details><summary># projects</summary><ul><li><a href="New Website.md" class="internal-link" data-href="New Website.md">New Website</a></li></ul></details> |
```

Каждый тоггл по умолчанию свёрнут — видно только название тега, пока по нему не кликнут. Обратите внимание: `# projects` — решётка с пробелом после неё (этот пробел важен: без него Obsidian может распознать текст как настоящий инлайн-тег и отрисовать вместо простого текста тег-«пилюлю» внутри тоггла, что визуально ломает заголовок). У строк «Без тегов» и `Obsidian` решётки нет вообще. Стрелка ↓ в шапке сейчас стоит на «Тег», потому что `tagSortBy` установлен в `name`.

> **Почему используются сырые HTML-теги `<a>`, а не `[[викиссылки]]`?** Obsidian не переразбирает содержимое внутри блока `<details>...</details>` как markdown — оно обрабатывается как обычный HTML-блок. Это значит, что синтаксис `[[викиссылка]]` внутри него так и остаётся текстом, а не превращается в ссылку. Чтобы ссылки оставались кликабельными, плагин генерирует настоящую HTML-разметку `<ul><li><a class="internal-link" data-href="...">` — Obsidian распознаёт класс `internal-link` и атрибут `data-href` и обрабатывает клик по ним так же, как по обычным ссылкам на заметки. Это проверено на основе наблюдаемого поведения рендеринга в реальном хранилище, а не по исходному коду самого Obsidian — если у вас какая-то ссылка не переходит к заметке, пожалуйста, сообщите, я поправлю.
>
> **Почему шапка таблицы — не кликабельный фильтр сортировки?** Официальная документация Obsidian по санитизации HTML подтверждает, что элементы `<script>` вырезаются из отрендеренных заметок ради безопасности — то есть у обычной сгенерированной заметки нет способа выполнить интерактивную логику сортировки по клику. Вместо этого «фильтр» реализован как настройка плагина и три команды в палитре команд (см. ниже) — выбираете режим сортировки там, и таблица сразу пересоздаётся в новом порядке, а активный столбец помечается стрелкой ↓ в шапке.

## Настройка

### Основные настройки
- **Язык**: русский или английский — переключает язык настроек, уведомлений и текста сгенерированной карты (подробнее выше, в разделе «Язык интерфейса»)
- **Имя файла карты**: можно задать любое имя для файла карты
- **Автообновление**: включает/выключает автоматическое обновление
- **Интервал обновления**: как часто обновляется карта (1–60 минут)

### Параметры отображения
- **Режим сортировки таблицы**: как упорядочивать строки тегов в таблице — по алфавиту, по количеству заметок или по дате самой свежей заметки (строки «Без тегов» и `Obsidian` всегда закреплены первыми и этой настройкой не затрагиваются)
- **Показывать дату изменения**: добавляет дату последнего изменения для каждой заметки внутри тоггла
- **Сортировка**: способ сортировки заметок *внутри* тоггла каждого тега (по имени, дате создания, дате изменения)

### Управление тегами
- **Включать вложенные теги**: обрабатывать иерархические теги с разделителем `/`
- **Показывать иерархию тегов**: создавать родительские теги для вложенных структур
- **Исключённые теги**: список тегов, которые нужно игнорировать (через запятую)

### Фильтрация содержимого
- **Исключённые папки**: список папок, которые нужно игнорировать (через запятую)
- Исключения по умолчанию: `.obsidian`, `.trash`

## Совместимость

- **Версия Obsidian**: требуется Obsidian 0.15.0 или новее
- **Платформы**: работает на Desktop, Mobile и веб-версии
- **Темы**: совместим с любыми темами
- **Другие плагины**: рассчитан на совместную работу с другими community-плагинами
- **Рендеринг тогглов**: тоглы `<details>`/`<summary>` разворачиваются свёрнутыми в режиме чтения (Reading view). В режиме **Live Preview** (редактирование) сырой HTML внутри ячеек таблицы может отображаться как подсвеченный исходный код вместо отрендеренного виджета — особенно рядом с курсором или до того, как Obsidian перерисовал эту строку. Это нормальное поведение редактора Obsidian, а не баг плагина. Переключитесь в Reading view, чтобы увидеть тоглы отрендеренными.
